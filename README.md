# 우리집 사진관 (photo_gallery)

**Synology NAS에서 직접 돌아가는 가족 사진 감상 웹앱**입니다. 가족이 각자 NAS
계정으로 로그인해, 공용·개인 사진을 연/월/일·인물·장소·비디오로 **감상**합니다.

<p align="center">
  <em>사진은 NAS 밖으로 나가지 않습니다. 클라우드도, 외부 AI도 쓰지 않습니다.</em>
</p>

## 사진 셋의 경계

| 앱 | 어디서 | 하는 일 |
|---|---|---|
| **우리집 사진관** (이것) | NAS 웹 | 가족이 공용·내사진을 감상 |
| **[Photo Desk](https://github.com/HyunjoonKwak/photo_desk)** | 맥 | 맥·NAS 1차 구역을 분류·정리해 공용·내사진으로 보냄 |
| **[Photo Backup](https://github.com/HyunjoonKwak/photo_backup)** | 안드로이드 | 폰 사진을 NAS 1차 구역으로 백업 |

사진은 `폰 → 1차 구역 → (Photo Desk 가 정리) → 공용·내사진 → (여기서 감상)` 순서로 흐릅니다.

**세 앱이 무엇을 주고받고, 무엇을 바꾸면 무엇이 깨지는지는 [ECOSYSTEM.md](ECOSYSTEM.md) 에 있습니다.**
서로 부르는 코드는 없고 NAS 위의 같은 폴더로만 이어지므로, 경로 합의가 어긋나면 **아무 오류 없이** 동작하지 않습니다.

> **정리 기능은 Photo Desk 로 넘어갔습니다.** 이 저장소에도 중복 찾기·잡동사니
> 걸러내기·폴더 이동 코드가 있지만, 무거운 판정은 전량 사본이 있는 맥에서 하는 것이
> 빠르고 안전합니다. 남아 있는 정리 기능은 맥이 꺼져 있을 때를 위한 예비입니다.

---

## 왜 만들었나

여러 사람이 여러 기기(폰·카메라·태블릿)로 찍은 사진이 NAS에 쌓이면 금세 엉망이 됩니다.
같은 사진이 여기저기 중복 저장되고, 날짜 폴더와 이벤트 폴더가 뒤섞이고, 정리하려니
파일 탐색기로는 너무 느리고 위험합니다.

- **Synology Photos**는 보기엔 좋지만 대량 정리(폴더 재편·중복 제거)가 불편합니다.
  → 이 앱은 **감상과 정리를 화면부터 분리**하고, 정리에는 다중 선택·드래그 이동·분할
    뷰를 제공합니다.
- **파일 탐색기 직접 조작**은 실수하면 복구가 어렵습니다.
  → 이 앱의 이동·삭제는 전부 **휴지통 + 작업 기록 + 되돌리기**로 안전합니다.
- **사진을 클라우드나 외부 AI에 올리는 것**은 개인정보가 걱정됩니다.
  → 모든 처리는 **NAS 안에서만** 일어납니다. 인물·장소 분류도 Synology가 이미
    만들어 둔 결과를 그대로 재활용합니다.

주 사용 환경은 데스크톱(넓은 화면에서 정리)이지만, 폰에서도 쓸 수 있게 반응형으로
만들었습니다.

## 화면 구성

앱은 세 영역으로 나뉩니다 — 앞의 둘은 **감상 전용**, 마지막이 **정리 전용**입니다.

### 📸 사진 — 타임라인 감상

- **연 / 월 / 일 / 폴더 줌** — 연·월은 작은 썸네일 바둑판으로 미리보기, 일은 그날 사진
  전부, 폴더는 실제 폴더 구조를 한 단계씩 탐색합니다.
- **날짜 스크러버** — 화면 오른쪽 막대를 잡고 원하는 연·월로 바로 점프합니다.
- **드릴다운** — 연 뷰에서 사진을 누르면 그 달로, 크게 보기(라이트박스)에서 촬영
  정보(EXIF)와 동영상 재생까지. 감상 화면이라 실수로 옮기거나 지울 일이 없습니다.

### 📔 앨범 — 인물·장소·비디오

- **인물** — Synology가 인식한 얼굴 그룹을 그대로. **이름 없는 인물에 이름을 지정**할 수
  있고, 이미 있는 이름을 고르면 **자동으로 합쳐집니다.** 같은 이름이 여럿이면 한 번에
  정리하는 **중복 병합**도 있습니다.
- **장소** — GPS 위치가 있는 사진을 **국가 → 지역**으로 묶어 폴더처럼 보거나,
  **지도 위 핀**으로 봅니다. 핀을 누르면 그 지역 사진으로.
- **비디오** — 라이브러리의 모든 동영상을 날짜별로 모아 봅니다.

### 🗂 폴더 분류 — 정리

- **폴더 탐색 & 분할 뷰** — 화면을 둘로 나눠 한쪽에서 고르고 반대쪽 폴더로 옮기는
  "정리 전용" 모드.
- **다중 선택 & 드래그 이동** — 여러 장 골라 폴더로 끌어다 놓으면 이동, ⌥(Option)이면
  복사. 버튼으로도 됩니다.
- **개인 → 공용 올리기** — 내 개인 폴더 사진을 가족 공용 폴더로. 기본은 원본을 남기는
  복사입니다.
- **폴더 관리** — 새 폴더, 폴더째 이동·복사, **같은 이름 폴더 합치기(merge)**, 폴더
  삭제(내용이 있으면 확인 후 통째로 휴지통으로).
- **중복 사진 정리** — NAS 전체를 스캔해 똑같은/비슷한 사진(연속 촬영 등)을 묶어줍니다.
  어느 것을 남길지 고르고 나머지는 휴지통으로. 절약되는 용량도 보여줍니다.

### 공통

- **모든 정리 작업 되돌리기** — 이동·복사·삭제·폴더 작업은 전부 기록되며, 화면의
  "되돌리기" 또는 작업 기록 패널에서 되돌립니다. 삭제는 영구 삭제가 아니라 휴지통으로.
- **가족 계정 & 관리자** — 각자 자기 사진을 정리하고, 관리자 계정은 (권한이 있으면)
  다른 가족의 개인 폴더 정리도 도울 수 있습니다. 이때 모든 작업은 "관리자 수행"으로
  기록됩니다.

## 필요한 것

- **Synology NAS** — Intel/AMD Plus 계열, **DSM 7.2 이상**, Synology Photos 사용 중
- **Container Manager**(Docker)가 설치된 NAS
- 가족 구성원의 **DSM 계정**(로그인에 사용)

사진 파일은 NAS의 Synology Photos 공유 폴더(`/photo`)와 개인 폴더
(`/homes/<사용자>/Photos`)를 그대로 사용합니다. 앱은 별도로 사진을 복제해 두지
않고, 항상 원본을 조작합니다.

> 인물·장소 앨범과 지도는 Synology Photos의 얼굴 인식·GPS 분류 결과를 재활용합니다.
> (지도 타일만 외부 지도 서비스에서 브라우저가 직접 불러오므로 지도 화면은 인터넷
> 연결이 필요합니다. 사진과 위치 데이터 자체는 NAS를 벗어나지 않습니다.)

## 설치 & 배포

미리 빌드된 이미지를 GitHub Container Registry(GHCR)에서 받아 NAS에 올립니다.
자세한 단계와 리버스 프록시(HTTPS) 설정은 [`DEPLOYMENT.md`](./DEPLOYMENT.md)를 참고하세요.

**요약:**

```bash
# 1) 로컬(개발 PC)에서 이미지를 빌드해 GHCR로 올림
#    (GHCR_USERNAME 환경변수 = 본인 GitHub 사용자명)
./manage.sh ghcr:push

# 2) NAS에서 이미지를 받아 배포
IMAGE_TAG=latest ./deploy.sh update
```

접속: `http://<NAS_IP>:9800`
운영 환경에서는 DSM 리버스 프록시(HTTPS) 뒤에 두고 쿠키 보안 옵션을 켜는 것을
권장합니다(자세한 내용은 `DEPLOYMENT.md`).

> **보안 참고 — DSM 자동 차단**: 이 앱은 로그인 요청을 NAS로 대신 전달합니다.
> 비밀번호를 여러 번 틀리면 DSM의 자동 차단이 도커 IP를 막아 **가족 전체가 로그인
> 못 할 수 있습니다.** DSM `제어판 → 보안 → 계정 → 자동 차단`의 허용 목록에 도커
> 게이트웨이 IP를 추가해 두면 안전합니다.

## 처음 사용하기

1. 브라우저로 `http://<NAS_IP>:9800`에 접속합니다.
2. **자신의 DSM 계정**으로 로그인합니다(2단계 인증을 쓰면 OTP도 입력).
   - 계정과 비밀번호는 앱이 저장하지 않습니다. 로그인 세션만 유지합니다.
3. 상단에서 **📚 라이브러리**(공용 / 내 사진)를 고르고, **영역**(📸 사진 / 📔 앨범 /
   🗂 폴더 분류)을 전환합니다. 감상은 사진·앨범에서, 정리는 폴더 분류에서 합니다.
4. **정리**는 폴더 분류에서 — 사진에 마우스를 올려 선택하고, 여러 장을 골라 폴더로
   끌어다 놓으면 이동됩니다(⌥ = 복사).
5. 실수했다면 화면 아래 **되돌리기** 또는 상단 **작업 기록**에서 되돌립니다.

## 데이터와 안전성

- **사진은 NAS를 벗어나지 않습니다.** 외부 클라우드·외부 AI로 전송하지 않습니다.
- **로그인 정보를 저장하지 않습니다.** NAS 세션 키는 서버 안에만 보관하고 브라우저에는
  노출하지 않습니다.
- **삭제 = 휴지통.** 영구 삭제가 아니라 앱 휴지통으로 옮기며, 되돌리거나 나중에
  "휴지통 비우기"로 완전히 지울 수 있습니다.
- **모든 변경은 되돌릴 수 있습니다.** 이동·복사·삭제·폴더 작업이 작업 기록에 남습니다.
- 앱이 관리하는 데이터(로그인 세션, 작업 기록, 중복 스캔 캐시)는 NAS의 작은 SQLite
  파일에 저장되며, 사진 원본과는 별개입니다.

## 개발자용

NAS 없이도 개발·체험할 수 있습니다. `.env`에 `MOCK_MODE=true`를 켜면 가짜 사진
데이터로 모든 기능이 동작합니다(운영에서는 절대 켜지 마세요).

```bash
# 백엔드 (FastAPI)
cd backend && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cd .. && MOCK_MODE=true uvicorn app.main:app --app-dir backend --reload --port 9800

# 프론트엔드 (Vite) — 다른 터미널에서
cd frontend && npm install && npm run dev
```

브라우저에서 <http://localhost:5173> 접속. `/api` 요청은 Vite가 백엔드(9800)로
프록시합니다.

- **기술 스택**: FastAPI(Python) · React + TypeScript + Vite · Zustand ·
  TanStack Query · Tailwind · Leaflet · SQLite. 파일 조작은 볼륨 마운트가 아니라
  **DSM Web API**(Auth / FileStation / Foto / FotoTeam)로만 수행하며, 권한은 DSM이
  강제합니다.
- **전체 명세**: [`NAS_사진정리앱_개발명세서.md`](./NAS_사진정리앱_개발명세서.md)
- **개선·결정 이력**: [`docs/IMPROVEMENTS.md`](./docs/IMPROVEMENTS.md)
- **배포 가이드**: [`DEPLOYMENT.md`](./DEPLOYMENT.md)
